# 开发计划：从单页平滑对比到应用实验室

状态：阶段 0 与阶段 1 的实现和自动检查已完成，等待用户检查讨论；阶段 2 尚未开始。见 [阶段 1 检查说明](stage1_review_zh.md)。

本文将 [应用分类规划](extension_plan_zh.md) 转化为具体开发顺序。分类文档定义长期范围；本文决定近期实现哪些内容、如何拆分代码、每一步做到什么程度。

## 1. 总体原则

- 继续使用 Streamlit + Plotly 和现有 Python 数值计算库，不更换前端技术栈。
- 先做一个完整可用的板块，再复用其流程扩展。每个阶段结束都能启动、调参和对比。
- 算法使用普通函数，页面使用普通渲染函数；只在实际出现重复时提取公共部分。
- 不引入插件系统、抽象基类、自动发现、通用工作流引擎或由配置自动生成所有页面的框架。
- 每个新板块先提供一个典型场景和两三种代表方法，再补充更多方法与场景。
- 沿用 A01–A12 作为文档和代码中的稳定标识，页面主要显示中文名称。

## 2. UI：一个工作区，三组应用导航

左侧仅负责选择应用；右侧按同一顺序展示内容：

1. 板块名称与一句话目标。
2. 数据/场景与执行模式。
3. 算法多选；已选算法的参数放在折叠区。
4. 主要对比图，优先占据页面宽度。
5. 简洁的指标表；误差诊断和算法说明按需展开。

不同时铺满所有算法的参数，不堆叠大量指标卡片。默认选中两三种方法，颜色在各图中保持一致；只计算选中的方法。

| 导航组 | 细分板块 | 实现顺序 |
|---|---|---|
| 信号恢复与结构保留 | A01 随机降噪、A02 趋势/基线/周期、A03 毛刺修复、A04 峰形保真、A05 阶跃保真 | 先 A01；再 A02 趋势、A03、A04；最后 A05 和 A02 扩展 |
| 变化、事件与状态 | A07 导数估计、A08 事件定位、A09 状态跟踪 | A07 紧随 A01；再 A08 和 A09 |
| 频率、累计与数据准备 | A06 频段提取、A11 积分、A10 包络/能量、A12 缺失/采样 | A06 → A11 → A10 → A12 |

只显示已经实现的导航项，不把尚未实现的页面做成空壳。最终三组都保留，但不要求先完成一整组才开发另一组。

第一版提供“离线对比”和“仅因果方法”。后者是在已有记录上验证因果算法，不等同于接入实时设备。固定延迟先显示为方法属性，专门的固定延迟筛选与回放在后续阶段增加。

离线对比允许同时展示因果和非因果方法，但明确标注其未来信息使用。因果筛选只保留经过验证的实现；不能仅修改标签就宣称支持实时。

## 3. 代码组织：职责分离，按需拆文件

初始目标结构如下，目录名是规划，不需要一次创建所有文件：

```text
app.py                   # Streamlit 入口、页面设置、应用导航
tslab/
    __init__.py
    data.py              # CSV 读取、合成场景、时间轴与输入校验
    algorithms.py        # 现有六种算法的纯计算函数
    metrics.py           # RMSE、MAE、RPR 等评价
    plotting.py          # Plotly 公共绘图函数
    ui.py                # 少量重复控件和公共结果展示
    applications/
        __init__.py
        denoising.py     # A01：组装数据、参数、计算、图表与指标
        derivatives.py  # 开发 A07 时再增加
        ...             # 每实现一个应用再增加相应文件
tests/                   # 核心数值性质、模式约束与关键冒烟测试
docs/
data/                    # 保留现有数据
styles.css               # 少量外观样式
requirements.txt
```

各部分的边界：

- `algorithms.py` 不导入 Streamlit，不负责画图，也不读取文件。函数名、参数和返回值应能直接用于独立实验脚本。
- 应用模块用明确的函数调用组织流程；可以有少量判断分支，不把所有逻辑塞进复杂配置字典。
- `plotting.py` 接收时间轴与命名曲线；`metrics.py` 接收目标数组、估计数组和有效掩码。它们不读取页面状态。
- `ui.py` 只提取已被多个页面使用的控件，不提前包裹每个 Streamlit API。
- `app.py` 仅维护简单的“显示名称 → 页面函数”映射。

算法数量增长后，再把 `algorithms.py` 拆成 `algorithms/smoothing.py`、`derivatives.py`、`frequency.py`、`state.py` 等。数据生成或指标也在内容变多时按职责拆分，不以文件越多为目标。

初期数据约定保持简单：

- 内部使用一维时间数组和观测数组；保留原时间戳用于展示，时间计算统一使用明确的单位。
- 合成数据按需附带同一时间网格上的干净信号、导数或事件真值，不存在的真值不伪造。
- 普通算法返回数组；需要多输出时返回有明确字段名的简单字典。导数结果使用 `signal`、`d1`、`d2` 等命名。
- 有效区域按输出分别记录；边界标记与“是否可计算”分开。待多个板块确有共享需求时，再考虑一个小型数据类。
- 不用一个包含所有未来功能的大结果对象；事件、状态协方差等在对应板块开发时再添加。

## 4. 开发阶段与验收

### 阶段 0：确认可运行基线

任务：在用户已有的 `ts_filter` 环境中检查依赖和启动方式，记录现有六种算法的默认设置及典型输出；列出已知参数问题。仅安装实际缺失的必要依赖。

交付：可靠的启动说明与现有行为基线，便于后续区分重构误差和有意修正。

验收：现有页面可打开，五个数据集可加载；实际失败项有明确记录。

### 阶段 1：统一工作区 + A01 随机降噪

任务按顺序执行：

1. 将数据加载、六种算法、图表和指标从 `app.py` 拆出，先保持正常输入下的既有计算行为。
2. 建立简洁导航和公共实验页面，迁移现有六种方法到 A01。
3. 加入带真值的合成正弦/慢变信号、噪声强度和固定随机种子。
4. 显示原始信号、真值及选中输出；增加 RMSE/MAE，RPR 作为辅助指标。
5. 独立修正参数校验与语义：明确 EMA 的 `adjust`、将 Kalman 参数明确标成方差、校验 SavGol 参数；不悄悄改变默认含义。
6. 加入后向 MA；因果方法启动区保留无效标记，不用未来回填。增加因果筛选和边界说明。

验收：原有能力保留；未选算法不执行；真实数据不显示虚假的真值误差；常数、短序列、无有效评价点和非法参数均有清晰处理。

阶段完成后即可作为第一个可用版本。

### 阶段 2：优先实现 A07 导数与变化率

先完成第二个导航组中的核心需求，验证公共结构能支持多输出：

1. 增加带解析一阶、二阶导数真值的正弦和多项式场景。
2. 实现直接差分、平滑后差分、SavGol 直接求导三条路线。
3. 原信号、一阶导、二阶导使用三行共享时间轴；各阶分别显示误差及有效点数。
4. 明确 Δt、单位和边界。因果模式只提供后向差分及因果预处理；居中 SavGol 不出现在因果列表。

验收：无噪声多项式的导数符合解析结果；改变采样间隔后量纲和数值正确；修改未来样本不影响因果输出的过去部分。

本阶段不加入三阶以上导数、自动参数寻优或高维状态模型。

### 阶段 3：补齐首组常见应用

依次实现，每个小步完成后即可使用：

| 小步 | 内容 | 首批算法 | 核心验收 |
|---|---|---|---|
| 3.1 A02 趋势 | 趋势估计与去趋势残差 | MA、Gaussian、LOWESS | 趋势真值对比；残差明确定义为观测减去估计趋势 |
| 3.2 A03 毛刺 | 展示修复值与修改位置 | 中值、Hampel | 注入异常有标签；同时检查异常区和正常区误差 |
| 3.3 A04 峰形 | 局部峰形放大和峰参数比较 | MA 基线、Gaussian、SavGol | 比较峰高、峰宽、位置；漏峰不当作已成功匹配 |

此阶段以复用现有算法为主，不同时加入样条、小波和多种分解方法。

阶段 1–3 构成核心学习版本：A01、A02 趋势、A03、A04、A07。

### 阶段 4：建立第三组基础应用

| 小步 | 内容 | 首批算法/流程 | 核心验收 |
|---|---|---|---|
| 4.1 A06 频段 | 低通、高通、带通和窄带干扰 | Butterworth、IIR 陷波；FIR 后补 | 已知多频信号上的频段衰减符合目标；采样率/截止频率有效；单向与双向明确区分 |
| 4.2 A11 积分 | 原始与处理后累计量 | 梯形积分、去基线后积分、降噪后积分 | 已知积分真值；展示总量偏差与累计漂移，而非只看平滑度 |

验收补充：非均匀采样不直接套用假设均匀采样的滤波器；先明确提示，自动重采样留到 A12。

### 阶段 5：结构、事件、状态与已有板块扩展

先实现 A05 中值/TV 阶跃保真 → A08 固定检测器下的事件对比 → A09 位置—速度 Kalman 与离线 smoother，再逐项补充 A02 的 STL/基线、A04 的小波、A07 的高斯/样条导数。

每次只加入一个应用或一种新的算法路线，不将所有候选方法作为同一批交付。

在这个阶段增加有限未来窗口的等待时间展示、固定延迟筛选，并验证数据逐步到达时已输出结果的可用性。不因接入离线 smoother 就宣称实现固定延迟处理。

验收：分别验证阶跃保留、事件匹配规则、状态单位和模型协方差；保留各方法的失败案例，避免只选有利场景。

### 阶段 6：进阶板块，按实际需求逐个实现

先 A10 包络/RMS，再 A12 缺失修复/抗混叠重采样；多传感器融合、EKF/UKF、自适应消噪放在后面。

不预先引入这些功能的专用框架或依赖。每项仍采用“典型数据 + 少量方法 + 任务指标”的小规模实现方式。

验收：包络与 RMS 的目标定义明确；缺失区单独评价；降采样有混叠对照；新增依赖和使用前提写入说明。

## 5. 每个开发小步的固定流程

1. 先确认目标输出、输入假设和最少的代表方法。
2. 编写或复用纯计算函数，先用带真值的小数据验证。
3. 接入应用页面和任务指标，只抽取实际重复的逻辑。
4. 做一次针对该变更的界面检查：切换场景、调整参数、取消全部算法、处理无效输入。
5. 更新使用说明及下面的进度清单，再进入下一步。

测试聚焦数值正确性、时间尺度、因果性、边界及有效区域，不为每个简单控件写重复测试，也不比较容易变化的截图像素。每个新算法至少覆盖一个明确的数值性质或已知真值案例。
