# 基础使用体验：语言、主题与后续建议

这是 A01 完成后的独立补充，不推进阶段 2 的导数功能。

## 本次实现

### 中英文

- 侧栏顶部提供“中文 / English”选择，默认中文。
- 应用导航、数据与算法选项、参数、说明、校验提示、指标表、图例和坐标轴同步翻译。
- `tslab/i18n.py` 集中管理文案；现有内部选项值、控件 key 和数值计算接口不随语言改变。
- 语言选择保留在当前 Streamlit 会话；切换语言保留实验参数和结果。刷新或重新连接后的跨会话偏好保存尚未实现。
- Streamlit 自带菜单和 Plotly 工具栏仍由框架管理，不属于本项目文案的翻译范围。

### 亮暗主题

- 在右上角原生菜单中使用 Light / Dark / System 按钮；没有另做一套侧栏主题开关。
- `.streamlit/config.toml` 分别配置亮色与暗色主题，控件、侧栏和表格由 Streamlit 同步适配。
- `st.context.theme.type` 将实际亮暗模式传给绘图函数；坐标、网格、观测、真值和算法线条使用对应配色，保留算法的颜色类别。
- 使用原生主题机制，不修改服务器全局配置，不依赖跨窗口脚本或私有前端事件来切换主题。
- 当前依赖声明为 `streamlit>=1.64,<2`，与本次验证环境一致。主题配置更新后，若运行中的服务没有刷新，请重启服务。

实现依据：[Streamlit 双主题配置](https://docs.streamlit.io/develop/concepts/configuration/theming)、[当前会话主题](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.context)。

## 验证与检查

20 项测试已通过。已有数值回归继续保留；增加语言往返切换、非默认参数保留、英文校验提示、翻译占位符一致性、图表亮暗配色以及模拟会话主题变化的测试。

### 更新代码后的旧进程问题

若看到 `TypeError: render() got an unexpected keyword argument 'language'`，而磁盘上的定义已经是
`render(language="zh", theme="light")`，可能是运行中的服务仍引用旧版模块。重新运行页面不一定能清掉旧引用，
应在启动服务的终端按 Ctrl+C，再执行原启动命令。不要删除 `language` 参数来绕过错误，否则会破坏语言切换。

本次曾在 8501 的实际 Streamlit 会话中复现此错误，同时 8502 正常生成两张图；重启 8501 后，
两个端口的实际会话均无异常，并各自生成两张图。
今后涉及入口与模块接口同步变更时，除了独立进程中的 AppTest，还要检查用户访问的服务进程。

建议打开页面后：

1. 改变 EMA α、样本数和所选算法，再切换 English，确认参数与指标数值未变。
2. 展开边界说明，检查图例、坐标轴、指标和提示是否一致切换语言。
3. 在右上角菜单切换 Light / Dark / System，检查图表、下拉框、参数控件和表格。
4. 切回中文与亮色，确认结果仍一致。

## 其他常用功能：分批实施，避免工具栏膨胀

| 优先级 | 功能 | 对本项目的用途 | 建议范围 |
|---|---|---|---|
| 优先 | 恢复默认参数 | 调参后快速回到可比较的起点 | 当前板块一个按钮，保留语言与主题偏好 |
| 优先 | 导出实验结果 | 用其他工具分析或保留学习记录 | CSV 输出时间、观测、真值和估计；另导出指标，保留无效点为空缺 |
| 随后 | 保存/加载实验配置 | 复现实验，不必重新调节参数 | 小型 JSON，记录场景、采样、噪声、种子、算法及参数；校验版本和输入 |
| 随后 | 导入 CSV | 比较自己的时间序列 | 选择时间与数值列，明确单位，校验重复/缺失/非均匀时间，不悄悄修复 |
| 按需 | 参数预设 | 快速观察弱/中/强平滑及典型失败情况 | 少量有说明的场景预设，不声称存在通用最优参数 |

图表缩放、平移、悬停和图例显隐继续使用 Plotly 自带交互；无需重复实现。暂不增加账号、数据库、权限系统或复杂任务管理。
