# 阶段 0：运行与计算基线

核验日期：2026-09-20。阶段 0 已完成环境、服务启动、应用交互和数值基线检查。未修改 `app.py`、算法实现或 conda 环境；阶段 1 尚未开始。

## 运行环境与启动

现有 `ts_filter` 依赖齐全，无需安装额外依赖。本次实测版本：Python 3.12.0、Streamlit 1.64.0、Pandas 3.0.6、NumPy 2.5.3、SciPy 1.18.1、Plotly 7.1.0、Statsmodels 0.15.0、PyKalman 0.11.2。这是环境记录，不是项目兼容性承诺。

在项目根目录启动：

```bash
conda activate ts_filter
python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

访问 `http://127.0.0.1:8501`。服务器已实际启动，健康检查返回 `ok`。如果 8501 已被占用，可更换端口；远程开发需要转发相应端口。

## 基线文件与复现

- [report.json](report.json)：依赖版本、源代码/数据 SHA-256、默认参数、数据质量、曲线摘要、显示的 RPR 及已复现异常。
- `curves.npz`：五个数据集的完整 35 条曲线（每个数据集含原始值及六种算法），用于重构后的数值对照。
- [采集脚本](../../scripts/capture_baseline.py)：仅针对当前原始 UI，不是未来页面必须兼容的公共接口。

此脚本保留作为阶段 0 的采集记录，仅在还原原始页面之后使用。当前 A01 页面请运行 README 中的单元测试，不用此脚本采集。还原后使用一个不存在的新目录：

```bash
conda run -n ts_filter python scripts/capture_baseline.py --output /tmp/ts-filter-baseline-review
```

脚本会故意触发上述两种非法组合，日志中出现对应异常是采集的一部分；正常数据集失败会中止采集。脚本拒绝覆盖已有目录，以免破坏参考数据。

重构对不变算法使用容差比较，例如 `np.testing.assert_allclose(..., rtol=1e-10, atol=1e-10)`；算法语义、边界或依赖发生有意改变时，应逐项解释差异，而非直接覆盖快照。基线记录的是历史行为，不证明算法本身最优或无误。
